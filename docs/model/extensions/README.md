# SOP 扩展接入契约

本目录是本仓库注册、激活和退役 BizDevOps SOP 扩展的唯一入口。核心四道 Gate 和三轴评审保持不变；扩展只增加专项产物、规则和检查，不重写基础流程。

## 机器可读注册表

[`registry.json`](./registry.json) 是扩展状态、类别、规则 ID 前缀和声明产物的权威事实源。**不要**在本 README 中复制状态表——它会与注册表漂移。

## 扩展生命周期

| 状态 | 含义 |
|---|---|
| `NOT_ENABLED` | 预留占位；不期望任何产物、规则或检查 |
| `DRAFT` | 产物和规则已存在，但尚未通过评审 |
| `ACTIVE` | 已评审并启用；声明的产物和检查必须存在且通过 |
| `RETIRED` | 不再强制执行；历史证据保留，不允许静默删除 |

扩展可以独立于核心模型状态进入 `DRAFT`。在切换到 `ACTIVE` 之前，其依赖的核心模型元素和自身产物都必须完成评审。启用扩展不会自动将核心模型提升为 `ACCEPTED`。

## 每个注册条目的必填字段

每个条目至少包含：

| 字段 | 用途 |
|---|---|
| `id` / `name` / `source` / `version` | 身份与来源；使用权威 SOP 内容，不得重建语法 |
| `status` | 上述四种生命周期状态之一 |
| `triggers` / `nonTriggers` / `audience` | 何时启用、何时不启用、目标读者 |
| `prerequisites` | 所需规范、核心模型元素、其他 SOP 或运行时能力 |
| `artifacts` | 扩展文档、契约增量、登记册、配置或测试的路径 |
| `gateHooks` | Gate B/C/D 的附加动作和退出条件 |
| `categories` / `ruleIdPrefixes` | 本扩展引入的新规则类别和稳定 ID 前缀 |
| `verification` | 自动化检查、语义评审、反向对照、工具版本和能力边界 |
| `outOfBand` | DSL/工具无法表达的信息由哪个版本化载体承载 |
| `owner` / `retirement` | 负责人、回顾方法、退役标准 |

稳定字段名（`id`、`status`、`categories`、`ruleIdPrefixes`、`artifacts`）不得跨项目改名，以保持跨仓库扩展协议兼容。项目可增加字段。

## 校验器如何发现扩展

校验器无条件加载核心类别。扩展类别仅在其模块为 `DRAFT` 或 `ACTIVE` **且**规则的 `sourceSops` 正确指向该模块时才参与检查。引用 `NOT_ENABLED` 模块的规则或产物视为错误。`ACTIVE` 模块若声明的产物或检查缺失也会失败。因此新增 SOP 只需增加注册条目——无需修改 schema。

## 接入新 SOP 的步骤

1. 阅读权威 SOP 章节；记录适用上下文、不适用场景和最小产物。
2. 在 `registry.json` 中注册；映射 Gate B/C/D 钩子。
3. 增加带 `sourceSops` 和稳定前缀的规则；扩展校验器而非硬编码绕过。
4. 在[评审模板](../review-template.md)中增加专项小节和最终证据要求。
5. 实现正向和反向检查；记录解析器/生成器/运行时验证的能力边界。
6. 在一个真实变更上试点，回顾文档负担与缺陷发现价值的比值，再决定 `ACTIVE`、进一步裁剪或 `RETIRED`。

全程核心四道 Gate、三轴评审和 A/B 漂移处置保持不变。
