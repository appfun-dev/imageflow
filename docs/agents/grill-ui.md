# Grill 问题澄清 UI（题波卡）

「题波」= 一轮并行呈现、等用户逐题拍板的开放问题集合（一次讨论可分多轮，第 1/2/… 轮）。「题波卡」把一轮题波渲染成交互问卷：一题一卡、用户整轮提交、agent 对账后批量落账。组件字段细节以 genui 技能为准；本文件只固定题波卡专属约定。

## 何时使用

- 设计 / 需求讨论中一轮开放问题成批涌现，向用户呈现一轮题波请求拍板；
- 用户要求以可视化交互形式出题（问卷卡 / 题波卡）；
- 处理题波提交后的 `[genui-action]` 回传。

## 卡片布局（一题一卡）

每题一个 `card`，内部顺序固定：

1. `card.title` = `Q<序号> · <主题>`，如 `Q7 · 缓存失效策略`；`card.accent` = 状态色——未作答 `#f59e0b`（琥珀）/ 已作答 `#3ecf8e`（绿），accent 同时染首行标题与边框，问题窗口呈信息框式提醒。
2. 正文 `text`：一两句问题主体，**加粗**待拍板的分叉点。
3. `radio`：每个子问题一个组，`group` = `q<序号>`（多子问题用 `q<序号>a` / `q<序号>b`）；选项标签以 `A · ` / `B · ` 开头，各带一句后果说明；末项固定为 `其他（下方输入框填写）`。重渲染时选中项标签加 `**粗体**`，并用 `selected` 预选回显——行内富文本不支持彩色文字，「选中项与首行同色」以整卡状态色 + 粗体表达。
4. `textarea`：`id` = `q<序号>-note`，`rows` 2，placeholder 给出示例格式；多子问题共用一个。
5. 底栏 `callout`：`tone:"info"`，`title` = `建议 ➡️ 选 <选项>`，正文 = 推荐理由 + 其余选项一句劣在哪。

状态色切换时机（渲染器现状，dsh-genui v0.14.0）：`accent` 是静态 spec 字段，点选瞬间不本地变色；轮内选中反馈由 radio 原生选中态与本地持久化承担。状态色随该题卡的**下一次重渲染**切换——首渲染一律琥珀 `#f59e0b`，对账 / 确认轮重渲染时把已作答题换绿 `#3ecf8e`、选中项加粗。

轮首放一条 `text` 说明题数与流程；轮尾放 `submit`：

- 中间轮 `label:"提交并继续"`，最后一轮 `label:"提交完成"`；
- `action` = `submit-<轮名小写>`，如 `submit-wave-a` / `submit-round-1`；
- `groups` 列全卡内所有 radio 组名——漏一个，该题答案不回传。

## 发出步骤

1. 组装 spec，调用 `validate_dsh_ui`；
2. `status=valid` 后在回答正文发出 `dsh-ui` 围栏；失败按诊断修复并重验。

完成判据：正文出现通过校验的围栏。

## 提交回传处理（对账流程）

实测回传 payload 只含 radio 组答案（`answers` 按 group 名索引）；textarea/input 自由文本不随 submit 回传。按序处理：

1. **补文本**：凡选中「其他」或「部分修改」而缺自由文本的题，先追问（重渲染补填卡或 prose 直问），该题暂缓落账。
2. **对账**：逐题将回传答案与决策台账（ADR / spec / 术语表等）比对。一致 → 确认；不一致 → 新提交优先，但旧台账曾把新选项列为被否备选时，把冲突与旧理由摆到 UI 与 prose 里，请用户 radio 二次确认（确认变更 / 撤销），不静默覆盖。
3. **批量修订**：一轮的全部变更合并一次落地——修订台账（ADR 追加修订记录、状态标 Amended）、同步术语表受影响词条、同步受影响的 spec / issue，一个 commit。

完成判据：每题要么「一致确认」，要么已落进修订后的台账，无悬空中间态。

## 状态

交互状态由平台按「会话 + 内容指纹」持久化，刷新 / 重放自动恢复已选项，新内容重置；卡片无需自行处理。
